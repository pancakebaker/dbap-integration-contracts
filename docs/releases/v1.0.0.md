# DBAP Integration Contracts v1.0.0

## Purpose

This is the first governed release of the language-neutral integration
contract set for the Distributed Bidding Auction Platform. It establishes a
stable baseline for independently versioned application repositories.

## Included surfaces

- JSON Schema Draft 2020-12 envelope and six event schemas;
- v1 golden fixtures for `BidAccepted`, `AuctionClosed`, and `WinnerSelected`;
- the current Bidding REST API in OpenAPI 3.1;
- current RabbitMQ channels and routing keys in AsyncAPI 2.6; and
- ownership, compatibility, and release governance documentation.

The release's wire baseline is commit
`6c89fb85d96110b881ff789470e3d7acfd5331e1`. The annotated `v1.0.0` tag is the
immutable release identity for this repository; governance files may be newer
than the original conformance snapshot while the wire artifacts remain the
same.

## Authority and consumers

Bidding owns auction, bid, tenant, lifecycle, winner, and final-price meaning.
Live Feed and Operations consume events into local projections. Laravel uses
the Bidding REST boundary through its BFF. The infrastructure repository owns
process orchestration only.

## Compatibility baseline

Money remains a JSON number, timestamps are ISO-8601 UTC strings, identifiers
use UUID-shaped strings, and distinct companion events may share an
`aggregateVersion`. Unknown additive properties are tolerated by current
consumers; unknown enum values are not assumed safe.

Three representative fixtures are currently canonical. The other three event
schemas are governed but do not yet have promoted golden examples.

## Upgrade guidance

Consumers should continue pinning exact contract commits. To adopt a later
release, update the repository-local test snapshot and provenance file, run
conformance, then release the consumer independently. No package publication,
generated client, or automatic consumer update is part of v1.0.0.
